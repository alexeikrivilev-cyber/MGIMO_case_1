# strategy-agent — «Стратег Фабрики продуктов»

Папочный ИИ-агент для руководителя цифрового продукта: репозиторий с
инструкциями, базой знаний и инструментами, который ведёт от размытого
запроса («почему падает удержание») до обоснованной продуктовой и
коммуникационной стратегии — и остаётся с ним после принятия решения
(реестр решений, план проверки, пересмотр при новых данных).

Это **не программа и не автономный агент**: это папка, которую открывают
в средах типа Cursor / Claude Code / GigaCode / Codex / OpenCode
(единый формат инструкций — `AGENTS.md`). Хакатон «Фабрика Продуктов»
(МегаФон), кейс «Стратег Фабрики продуктов».

Демо-проект (задача РП, открытые данные, все артефакты полного пути) —
в [`project/`](project/README.md). Измерения, на которых держатся
решения об архитектуре, — в [`docs/research/measurements.md`](docs/research/measurements.md).

## 1. Быстрый старт

### 1.1 Проверить репозиторий — без ключей и без оплаты

Всё, что агент производит, проверяется детерминированными гейтами и
тестами; они не требуют ни ключей, ни сети. Единственная сторонняя
зависимость — `pytest` (для тестов); все гейты и скрипты работают на
стандартной библиотеке:

```bash
python3 -m venv .venv && . .venv/bin/activate    # изолированное окружение (один раз)
python3 -m pip install -r requirements.txt        # единственная зависимость — pytest
python3 -m pytest tests/ -q                                   # 464 теста
python3 scripts/check_state.py                                # STATE.md цел
python3 scripts/check_sources.py project/brief.md project/research.md \
  project/options.md project/strategy-product.md \
  project/strategy-comms.md project/verification-plan.md \
  project/decisions.md                                        # каждый факт несёт основание
python3 scripts/check_evidence_links.py --task all            # число → содержание evidence
python3 scripts/check_acceptance.py project/strategy-product.md   # 6 вопросов владельца
python3 scripts/cost_report.py                                # сводка расходов
```

Демо читается напрямую: `project/README.md` → `project/brief.md` →
`research.md` → `options.md` → `strategy-product.md` →
`strategy-comms.md` → `verification-plan.md` → `decisions.md`.

### 1.2 Запустить агента — что нужно заранее

| Что | Зачем | Обязательно? |
|---|---|---|
| Python 3.10+ (желательно venv) + pytest (`requirements.txt`) | тесты и гейты | да |
| Node.js 18+ | плагин хуков (`.opencode/`) | да для прогона агента |
| OpenCode CLI (`opencode`, проверено на 1.19.5) | целевая среда запуска | да для прогона агента |
| **Ключ StepFun API** (`STEPFUN_API_KEY`) | **платный сервис**: модель `stepfun/step-5-preview`, ~$1.00/M input, ~$2.70/M output (прайс — `docs/research/llm-pricing-agent-costs.md` §1.8) | да для прогона агента; ключ только через env, никогда в репозиторий |

Другие провайдеры возможны: модель и baseURL задаются в
`.opencode/opencode.json` (сейчас — StepFun через OpenAI-совместимый
эндпоинт). Скрытых настроек нет: конфиг лежит в репозитории, все
секреты — через окружение.

```bash
# 1. Ключ — только через окружение (в репозиторий не попадает):
export STEPFUN_API_KEY=<ключ StepFun>

# 2. Зависимости плагина хуков (один раз, из корня репозитория):
cd .opencode && npm install && cd ..

# 3. Прогон агента из корня репозитория:
opencode run "Выполни шаг 0 (рамка) по демо-задаче eval/tasks/demo-retention/task.md"
```

Что происходит внутри: инструкции грузятся из `AGENTS.md`; навыки —
из `knowledge/index.md` по шагу; после каждой записи `project/*.md`
хук `.opencode/plugins/strategy-hooks.ts` прогоняет гейты
(`check_sources`, `check_transferability`, `check_ranges`,
`check_complexity`, для `strategy-product.md` ещё `check_acceptance` и
`check_actionability`); на каждом сообщении ассистанта хук дописывает
строку учёта в прод-таблицу `COST.md`; состояние шага живёт в
`STATE.md` — прерванный прогон продолжается новым чатом
(`opencode run "Прочитай STATE.md и LOG.md (навык resume) и продолжи"`).

Сколько стоит: одна сессия шага — **$0.3–0.6**, полный путь демо-кейса
(шаги 0–5, 22 сессии, включая критика и раунды ревизии) — **$2.67**
(строки с меткой «t18-case» в `COST.md`; итог по всем контурам —
`cost_report.py`). Ориентир ТЗ «полный прогон mid-tier ≤$2–5» —
выполнен.

### 1.3 Полный путь кейса целиком (как в демо)

Демо-прогон, артефакты которого лежат в `project/`, воспроизводится
драйвером `eval/run_full_case.py` (шаги 0–5, гейты с явными кодами
возврата, ревизионные раунды по выводам гейтов, критик-детектор на
шагах 4–5, идемпотентность переиспользования зелёных артефактов):

```bash
export STEPFUN_API_KEY=<ключ StepFun>
python3 eval/run_full_case.py --task demo-retention --dry-run   # показать план, не тратить
python3 eval/run_full_case.py --task demo-retention             # прогнать (~$2–3)
```

Журнал прогона (какие сессии, какие раунды ревизии, коды гейтов,
sha256 артефактов) — `eval/runs/t18-case/manifest.md`.

## 2. Архитектура

Слои (принцип «порядок в знаниях» — постоянные инструкции, методика,
материалы проекта и состояние задачи хранятся раздельно):

| Слой | Где | Что |
|---|---|---|
| Постоянные инструкции | `AGENTS.md` | workflow с шагами 0–5 и чекпоинтами, границы, дисциплина доказательств; рабочий черновик — `docs/agents-md-staged.md` |
| Методические знания | `knowledge/skills/*` | 7 навыков (framing, evidence, resume, options, strategy-product, strategy-comms, verification) + `critic`, `decisions`; карта «вопрос → навык» — `knowledge/index.md`; черновики — `knowledge/skills/_draft/` |
| Шаблоны | `templates/` | по файлу на артефакт шага |
| Состояние задачи | `STATE.md` + `LOG.md` | resume-карта и журнал действий (append-only) |
| Прозрачность стоимости | `COST.md` | dev/prod контуры, хук `cost-append` |
| Материалы проекта | `project/` | рамка, evidence, артефакты пути |
| Гейты | `scripts/check_*.py` | 14 детерминированных проверок (см. §1.1 и таблицу ниже) |
| Хуки | `.opencode/plugins/strategy-hooks.ts` | гейты на записи `project/*`, индекс навыков, `STATE.md`; учёт стоимости на каждом сообщении |
| Стенд измерений | `eval/` | рубрики 1:1 из критериев хакатона, A/B-руки, полный путь, критик-детектор, ось слепых зон; бенчмарк DABstep в Docker |
| Самоулучшение навыков | `product/agent/` | журнал мутаций (блобы sha256), предохранитель «только по замеру», откат fail-closed |

Процессы: агент ведёт РП по шагам (рамка → материалы → исследование →
варианты → стратегии → решения), на существенном выборе подключается
человек (чекпоинты 1–3), после решения — реестр решений с условиями
пересмотра. Работа с контекстом: входы артефакта передаются сессии
инлайном (файлы не открываются — контракт сессий, устраняющий потерю
выхода на границе CLI/провайдера), большой промпт режется
`chunk_prompt` (защита от E2BIG).

Гейты и что именно они ловят:

| Гейт | Класс дефекта |
|---|---|
| `check_sources.py` | числовое утверждение без основания в строке; секция без ссылки |
| `check_evidence_links.py` | «ссылка есть, содержания нет»: число не резолвится в cited ev-N |
| `check_citations.py` | резолвимость URL (живая проверка — браузером) |
| `check_transferability.py` | перенос чисел/причин аналога на сервис без маркера |
| `check_options.py` | <3 вариантов, нет «оставить как есть», нет возражений/маркеров |
| `check_decisions.py` | решение без владельца/метрики/условия пересмотра/даты |
| `check_acceptance.py` | приёмный чек-лист 6 вопросов владельца |
| `check_actionability.py` (v2) | план без структурных признаков (P0–P2, метрики, «не работает») |
| `check_complexity.py` | управляемая сложность набора вариантов |
| `check_ranges.py` | диапазон без основания в строке |
| `check_state.py` | схема STATE.md (9 обязательных секций) |
| `check_skill_index.py` | индекс навыков ↔ SKILL.md (обе стороны) |
| `check_commit_scope.py` | состав индекса коммита (не только TASK-файл) |
| `check_pyright.py` | статический анализ типов новых файлов |

## 3. Ключевые решения (каждое — с замером)

Полные протоколы и предрегистрации — `docs/research/measurements.md`;
здесь — решения и их основания.

1. **Прирост несут инструкции и навыки, не число агентов.** Абляция
   слоёв L0→L4 на замороженном брифе (демо + held-out, шум судьи
   измерен, MDD 4.08): обычный чат 24/25, +AGENTS.md 30/32, +навыки
   37/38, +гейт проверок 37/36, полный продукт 39/40 по типовой
   рубрике (§23.5). Остаточная сложность агента — на границе шума
   (+4.0 ± 4.1, интервал накрывает 0) → развилка закрыта.
2. **Гейты — детектор, не оценщик.** Гейт проверок не поднимает балл
   (−2.00 ± 4.06), но ловит реальные структурные дефекты: 44 находки
   на артефактах шагов 4–5, ~93% подтверждены при ручной разборке.
3. **Критик — детектор с изолированным контекстом, не «улучшатель».** Четыре
   независимых измерения улучшательных гипотез (critic-loop на шагах
   2/4, второй раунд ревизии, патчи навыка по ощущению) не дали
   прироста выше шума (§22.4/§22.7/§23.6/H-C2/H-SI1). Оставлен как
   детектор: находить слабые места до человека.
4. **Консилиум: полный — в разработке, council-lite — в проде.**
   council-lite бьёт базу на обеих задачах (+4/+4, §14); полный
   протокол на held-out дал +2 < MDD при цене 5.7× → прод-кандидат
   council-lite, полный — dev-инструмент (§16). Триггер «высокая
   ставка» — 10/10 срабатываний, 0 пропусков.
5. **Человек-судья — главный ground truth.** 10 слепых пар (ослепление
   по seed, ключ после суждения): skill 2-0 в вилках прод-конфига,
   курация навыков 3-0 над lean; обычный чат выиграл 3:1 в парах, где
   отвечал на вопрос целиком (вход назван неэквивалентным — артефакт
   шага 3 намеренно останавливается на вариантах). Отсюда решение:
   шаги 4–5 ответственны за «готовность к действию» — план, метрики,
   критерии остановки.
6. **Аддендум критика не валидирован.** Пункты слепых зон подняли
   согласие с человеком 1/7 → 4/7, но перевернули контрольную пару →
   вердикт по предрегистрации: НЕ ВАЛИДИРОВАН (§30.2). Ось остаётся
   диагностикой; итоговый балл — база 1:1.
7. **Самоулучшение навыков — только по замеру.** Предохранитель
   `product/agent/skill_guard.py` требует артефакт замера до записи
   (негативный контроль: заметка вместо замера → отказ). Механика
   версионирования/откат — из изучения Hermes, адаптирована.
8. **Шаг 3 в проде — база (навык options) + критик-детектор на шагах
   4–5.** council-lite и critic-loop2 на шаге 3 проиграли базе в
   суждениях человека (сходится с замерами).
9. **Дефекты стенда находились живыми прогонами и исправлялись по
   классу**: потеря финального текста сессии на границе CLI/провайдера
   (контракт переведён на инлайн входы + порог годности артефакта),
   пустой выход критика при exit=0 (гейт), парсер частичной оценки
   (менял знак Δ серии), гонка метки прогона (вынесена в
   `eval/.cost-label`). Провальные и отвергнутые прогоны сохранены и
   опубликованы, не спрятаны.

не подтвердилось — названо отрицательным результатом, а не спрятано.

| Критерий | Чем закрывается | Подтверждение |
|---|---|---|
| **1. Проработанность** | Демо-артефакты: маркеры [факт]/[гипотеза]/[прогноз]/[допущение], ссылки ev-N с резолвимым содержанием, 4 варианта с разными механизмами + «оставить как есть» с ценой бездействия, согласованные продуктовая и коммуникационная стратегии, план проверки с порогами, приёмный чек-лист 6/6 | 13 файлов зелёные под `check_evidence_links`, 6/6 URL живые (`check_citations`), гейты строгого режима exit 0 |
| **2. Масштаб нейротехнологий** | Агентная система: workflow + чекпоинты, слои знаний, resume, критик с изолированным контекстом, Консилиум (два контура), гейты, хуки, самоулучшение навыков, стенд измерений с бенчмарком DABstep | У каждой фичи — строка «фича → метрика → результат → решение» в measurements.md; неподтвердившиеся (аддендум, второй раунд ревизии, flash-демейшн, явный кэш) — отрицательные результаты с данными |

## 5. Экономичность (время и расходы)

- **Полный путь демо-кейса** (шаги 0–5, прод-конфиг): 22 сессии,
  **$2.67**, включая критика-детектора и раунды ревизии ($0.25 из них —
  потерянный прогон дефектного контракта сессий, учтён как затраты).
  Сессии идут последовательно с гейтами между ними, поэтому машинное
  время прогона — порядок нескольких часов; участие человека —
  чекпоинты 1–3 и утверждение на шаге 4.
- **Одна сессия шага**: $0.3–0.6 (step-5-preview, кэш префикса даёт
  естественную экономию ~$0.18/руку — замер §19.3).
- **Весь проект** (разработка + все замеры, оба контура): **$57.18**
  по `cost_report.py` на момент сдачи; dev-контур без ограничений по
  правилу владельца, но каждая строка учтена.
- **Held-out полный путь** (симметрия демо, задачу «ДомКниг»): 23 сессии,
  $3.00 — первый запуск потерян дефектом «пустой выход», возобновление
  зелёное (`eval/runs/t18-case-heldout/manifest.md`).
- Обычный чат на том же брифе: $0.06 (замер B11) — но без оснований,
  ссылок и плана проверки; агент дороже чата и этот прирост измерен
  абляцией, а не заявлен.

## 6. Удобство

- **Остановить**: прерывание в любой момент (Ctrl-C / внешний kill) —
  состояние в `STATE.md`, продолжение новым чатом без потери шага
  (реальный прецедент — возобновление task 18 после SIGINT).
- **Уточнить**: чекпоинты 1–3 — короткая сводка «что знаем / чего не
  знаем / что решаем», агент не проходи́т их молча.
- **Исправить**: гейты показывают строку и причину; ревизионные
  правки точечные (`scripts/apply_revision.py` с integrity-гейтом:
  заголовки, «оставить как есть», размер ≥60%).
- **Понять, что делает агент**: прогресс виден (манифест прогона,
  журнал LOG.md, строки стоимости в COST.md), каждый вывод несёт
  основание, пробелы названы явно.

## 7. Ограничения (названы, не спрятаны)

- **Оценка качества — self-assessed proxy.** Внешних экспертов нет;
  критик с изолированным контекстом — внутренний механизм (BRIEF п.16).
  Изоляция — уровня промпта, не sandbox: сессия с инструментами в
  принципе может читать файлы (прецедент зафиксирован, ущерба не было).
- **Демо-сервис вымышленный.** «МегаТВ Онлайн» — сценарий; данные —
  открытый датасет-аналог (IBM Telco Churn). Перенос драйверов на
  стриминг — [гипотеза], денежные показатели аналога не переносятся
  (гейт `check_transferability`).
- **Денежный ROI не посчитан намеренно**: ARPU и суммы spend'ов
  неизвестны — экономика дана в структурных единицах (п.п. удержания,
  спасённые подписно-месяцы).
- **Шум измерений**: правило «n=1 = suggestive»; шум судьи измерен
  (sd 1.03), MDD пересчитан из него; часть клеток серий — на границе.
- **Held-out прогон полного пути** (`eval/runs/t18-case-heldout/`):
  первый запуск потерял шаг 3 — две сессии вернули пустой выход при
  exit=0 (дефект класса «пустой выход», $ учтены); возобновление прошло
  весь путь зелёным (23 сессии, $3.00; ревизионные раунды: options ×2,
  strategy-product ×4, comms ×1, verification-plan ×1, decisions ×1 +
  критик-детектор на шагах 4–5). Итог — в его manifest.
- **Видео и PDF-описание** — deliverables PO вне репозитория; материалы
  для них (6 разделов ТЗ) собраны в `docs/submission/`.
- **Целевая среда** — OpenCode CLI; другие среды работают через
  `AGENTS.md` (портируемость описана, но матрица сред неполная —
  `docs/portability.md`).

## 9. Проверки и состав репозитория

- **Тесты**: `python3 -m pytest tests/ -q` — 464 зелёные (в т.ч. тесты
  на живом хуке, негативные Controls гейтов, регрессы на
  закоммиченные артефакты).
- **Секреты**: ключи только через окружение (`.opencode/opencode.json` —
  `{env:STEPFUN_API_KEY}`); `.gitignore` исключает `.env*`, логи хуков,
  `node_modules`, метку прогона; аудит при сдаче — файлов с ключами,
  персональных данных и закрытых данных МегаФон не найдено.
- **Логи прогонов**: в `eval/runs/` сохранены manifest, сводки и
  артефакты; служебные `.start/.end/.err` сессий убраны (1546 файлов) —
  они воспроизводимы перепрогоном и не несут содержимого.

Портируемость: единый источник истины — `AGENTS.md` (стандарт
agents.md); навыки видны средам через симлинки `.claude/skills` и
`.agents/skills` → `knowledge/skills`; Gemini CLI требует односточной
настройки `context.fileName` (источник — документация + issue
google-gemini/gemini-cli#28227, проверено 2026-11-16).
