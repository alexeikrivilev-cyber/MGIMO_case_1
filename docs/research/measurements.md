# measurements.md — измерения фич «Стратега» (О3, живой документ)

> Правила (ROADMAP, правило останова; PRD §15 DoD): у каждой фичи с
> бенчмарком — строка «фича → метрика → результат → решение» + история
> итераций. Всё, что не полный бенчмарк, помечено **proxy** (решение PO

> self-assessed (двухпроходная self-consistency), судьи-LLM — только
> secondary. Отрицательные результаты пишутся наравне с положительными.

## 0. Предрегистрированное правило демоции Консилиума (цитата из council-design.md §6)

Источник правила — `docs/research/council-design.md` §6 (согласован с PO
как часть PRD v1.1); цитата дословная:

> Консилиум идёт в прод **iff** A3/A4 бьют A1 по разнообразию (diversity)
> **И** по качеству возражений с маржой больше предрегистрированного MDD
> (~1 балл рубрики / полный rank-swap), при стоимости, которую принимает
> прод-бюджет. Если A1 ≈ A2/A3 в пределах шума → в прод идёт A1
> (мульти-линза одним вызовом), отрицательный результат фиксируется
> честно. Если A3 > A2 (гетерогенность важна) → прод использует
> гетерогенный mini (2 семейства, 3 роли).

Правило зафиксировано ДО измерений О3 (источник — council-design.md,
согласован с PO как часть PRD v1.1). Ниже — применение по факту.

### 1.5 Решение по предрегистрированному правилу

Правило — `docs/research/council-design.md` §6 (цитата в §0 этого
файла); факты — измерения §1.1–1.4 этого же файла и строки
`COST.md` по сессиям прогона.

| Условие правила | Факт | Вердикт |
|---|---|---|
| diversity > MDD над A1 | 0.935 vs 0.963 (прокси насыщен) | **not met as measured** |
| качество возражений > MDD над A1 | +1.0 (оба прохода) | met (на границе) |
| качество стратегии > MDD | +5 / +3.5 | met |
| стоимость приемлема для прода | $0.58 vs $0.05 (~10×) | нет для прод-цели ≤$2–5/прогон council-off |

**Решение (О3):** полный Консилиум НЕ идёт в прод — правило требует
оба условия качества, diversity-condition не выполнен как измеренный.
В прод-кандидаты идёт **A1 (мульти-линза одним вызовом)**: ≈10× дешевле,
качество возражений в пределах MDD. Полный Консилиум остаётся
инструментом dev-контура (генерация инвентаря + защищённый адвокат для
высоких ставок). Отрицательный результат записан честно, как требует
правило. **Оговорка для О4:** diversity-условие измерено насыщенным
прокси — перепроверка на стенде О4 либо реальными embeddings (если
появится провайдер), либо экспертным подсчётом содержательно разных
механизмов (кластеризация вариантов экспертом).

## 3. Устойчивость (B5) — fault-injection прогоны (PRD §12)

Все три сценария проведены реальными прогонами 2026-11-16 (не
утверждения): скрипты — `scripts/fetch_with_retry.py`,
`scripts/recover_state.py`; сценарий и вывод FI-1 —
`eval/fault-injection/`.

| FI | Введённый сбой | Что произошло (факт) | Вердикт |
|---|---|---|---|
| FI-1 | сетевой источник недоступен (connection refused, порт 1) | retry сработал: 3/3 попытки, backoff 1.69s → 2.56s (exp+jitter), exit 2; запись-пробел напечатана; агент продолжил путь на локальном CSV (7 043 записи, отток 26.54% — совпало с `ev-002` независимым пересчётом), пробел назван явно со статусом «не проверена»; артефакт создан, `check_sources.py` по нему exit 0; посторонних записей в репозитории нет | путь продолжился ✓ |
| FI-2 | STATE.md битый (перезапись мусором) | `check_state.py` → exit 2 (9 нарушений); `recover_state.py` восстановил из последней валидной git-версии (af3dc65), diff с бэкапом — идентичен; проверка после восстановления exit 0 | восстановление ✓ |
| FI-3 | «мусорный» артефакт (варианты без структуры; исследование без оснований) | `check_options.py` → exit 2 (нет секций вариантов); `check_sources.py` → exit 2 (секция без ссылки + числовое утверждение без основания) | артефакт не коммитится ✓ (гейт детерминированный) |

Что чинилось по результатам: ничего в агентах — механизмы отработали
с первого прогона; но найдено и исправлено ранее (в рамках B1): дефект
учёта стоимости (§2), который искажал замеры всех прогонов.
Покрытие тестами: 12 новых тестов на контракты обоих скриптов
(99 всего зелёные).

Не покрыто (честный пробел): сбой «модель вернула мусор/обрыв» —
PRD §12 требует «артефакт не коммитится; шаг повторяется»; частично
проверено лишь через FI-3 (гейт блокирует), но не полный сценарий
«обрыв посреди шага → повтор с другой моделью/effort». Зафиксировано
как кандидат в стенд О4.

## 8. MCP web-search (B4) — решение с обоснованием

## 12. Агент-критик с изолированным контекстом (BRIEF п.16) — приоритет 1

**Гипотеза (новая, не измерялась в О1–О3):** внутренний критик со свежим
контекстом находит существенные находки, которые самооценка автора
пропускает (self-assessment bias); механизм оправдан, если расхождение
выше предрегистрированного MDD.

**Протокол (предрегистрирован до прогонов):**
- Навык — `knowledge/skills/critic/SKILL.md`; runner —
  `scripts/run_critic.py` (свежая сессия opencode, артефакт + рубрика
  инлайном, чтение файлов проекта запрещено инструкцией).
- Рубрика — `eval/rubrics/hackathon-criteria.md` (1:1 из критериев
  хакатона, 4 × 10, шкала 1–5, два прохода).
- Матрица — `eval/run_critic_matrix.py`, артефакт —
  `eval/runs/critic-matrix/` (13 артефактов: 7 демо + 6 held-out; на
  каждом два режима: `critic` и `self`; порядок сбалансирован).
- **Правило вывода (предрегистрированное):** находка критика важности
  ≥ «важно», которой нет в self-выходе → механизм оправдан (bias
  снижается). MDD: расхождение по критерию ≥ 0.5 балла ИЛИ ≥ 1 важный
  пропущенный finding. Иначе — честный negative result.
- Все замеры — self-assessed proxy (R3); критик помечен как внутренний,
  не внешняя экспертиза.

**Итерация 1 (гипотеза):** механизм находит пропуски самооценки.
Прогон: `eval/runs/critic-matrix/` (26 сессий, метки «О4: m-…» в COST.md).
Статус: прогон выполнен 2026-11-16; анализ — ниже, в §12.1.

### 12.1 Результат итерации 1 (2026-11-16)

Прогон завершён: 26/26 сессий exit 0, ~$1.30 (атрибуция: 21 строка
COST.md с меткой «О4: m-…» = $1.10 + 5 ранних прогонов до появления
метки ≈ $0.2 — по порядку завершения). Анализ —
`eval/runs/critic-matrix/analysis.md` (+ `analysis.json`).

**Оценки (рубрика /40, два прохода):**

| Артефакт | critic | self | Δ | findings c/s |
|---|---|---|---|---|
| demo brief | 20 | 18 | +2 | 7/5 |
| demo research | 14 | 22 | −8 | 6/11 |
| demo options | 22 | 26 | −4 | 8/7 |
| demo strategy-product | 24 | 26 | −2 | 7/8 |
| demo strategy-comms | 20 | 24 | −4 | 7/8 |
| demo verification-plan | 24 | 26 | −2 | 5/2 |
| demo decisions | 26 | 26 | 0 | 6/6 |
| heldout brief | 14 | 26 | −12 | 6/5 |
| heldout research | 18 | 20 | −2 | 5/6 |
| heldout options | 26 | 24 | +2 | 6/6 |
| heldout strategy-product | 24 | 26 | −2 | 9/6 |
| heldout strategy-comms | 24 | 24 | 0 | 4/3 |
| heldout verification-plan | 22 | 24 | −2 | 9/8 |

**Вердикт по предрегистрированному правилу: механизм ОПРАВДАН.**
Автоматический список «critic-only» — эвристика (грубое совпадение
слов), поэтому вывод проверен чтением на выборке из 5 артефактов:

| Артефакт | Важные находки критика, пропущенные self (проверено чтением) | Важные находки self, пропущенные критиком |
|---|---|---|
| demo brief | тарифная сетка исключена двумя разными способами; нет горизонта измерения эффекта | маркеры [факт]/[прогноз] не расставлены |
| demo decisions | числа D4 (тренд −13 п.п.) без ev-N в строке; замер совета упомянут, но без цифр | — |
| demo verification-plan | 3 важные: [факт]-маркеры на числах аналога; порог И3 −3 п.п. произволен относительно ev-003; нет ссылок на measurements/COST | self дал 0 находок |
| heldout brief | утверждения «URL проверены» без зафиксированного результата; решающий вопрос 3 без дефолта; нет следов STATE/LOG/resume | аналитический вывод без маркера |
| demo options | 3 незначительные (определения 58.05%; консистентность [факт]; шкала обратимости) — важные находки критик и self нашли одни и те же | пороги/условия отказа/замеры — общие с критиком |

**Закономерности (честно, обе стороны):**
1. **Критик систематически строже:** Δ ≤ 0 на 9/13 артефактов, медиана
   −2; худший случай −12 (held-out brief: критика «ширина рубрики vs
   один артефакт»). Самооценка систематически щедлее — измеряемый
   self-assessment bias (то самое, что механизм и должен был ловить).
2. **Критик не доминирует:** на research/strategy-артефактах self
   нашёл важные вещи, которых нет у критика (маркерная дисциплина,
   ссылки на measurements). Линзы ДОПОЛНЯЮЩИЕ, не «критик лучше».
3. Обе руки попадают в ловушку масштаба: рубрика системная
   (4 критерия хакатона), артефакт — один шаг; итог /40 частично
   измеряет полноту вырезки. Это дефект метода замера, не агента.

**Дефект замера, найденный и исправленный в анализе:** парсер находок
не считал формат «[важность: важно]» (только короткий «[важно]») —
счётчик findings был занижен на 3 артефактах (в т.ч. research: 0 vs 6).
Исправлено в `eval/analyze_critic_matrix.py`; урок: формат выхода
оценщика надо валидировать схемой, а не регуляркой «на глаз».

**Решение (кандидат в фичу продукта, B-уровень):** внутренний критик
идёт предкоммит-гейтом для артефактов шагов 4–5 (strategy-*,
verification-plan, decisions) — там self дал 0–2 находки, критик 3–5.
Не идёт заменителем self-оценки: на research/options self полезнее.
Статус фичи: **итерируется** (итерация 1 завершена; следующие
гипотезы — §12.2).
