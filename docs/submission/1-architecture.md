# 1. Архитектура

## Что это

«Стратег» — ИИ-агент как репозиторий-папка: инструкции (`AGENTS.md`),
база знаний (`knowledge/`), шаблоны (`templates/`), инструменты
(`scripts/`, `.opencode/`), состояние задачи (`STATE.md`, `LOG.md`,
`COST.md`) и материалы проекта (`project/`). Открывается в средах типа
Cursor / Claude Code / GigaCode / Codex / OpenCode; целевая среда
разработки и прогонов — OpenCode CLI.

## Процессы

Workflow с шагами и чекпоинтами (AGENTS.md §1):

```
Запрос РП
   ▼
[Шаг 0] РАМКА ──────────── ЧЕКПОИНТ 1 (человек подтверждает рамку)
   ▼
[Шаг 1] МАТЕРИАЛЫ ─────── (человек может догрузить/отклонить источники)
   ▼
[Шаг 2] ИССЛЕДОВАНИЕ ──── ЧЕКПОИНТ 2 (человек утверждает план/решающие вопросы)
   ▼
[Шаг 3] ВАРИАНТЫ ──────── ЧЕКПОИНТ 3 (человек выбирает вариант или возвращает)
   ▼
[Шаг 4] СТРАТЕГИИ (продукт + коммуникация + план проверки)
   ▼
[Шаг 5] ПОСЛЕ РЕШЕНИЯ: decisions.md, пересмотр при новых данных
```

Правила шагов: уточнять только то, что меняет следующий шаг (не более
3 обязательных чекпоинтов на прогон); на чекпоинте — сводка «что
известно / чего не знаем / что решаем»; останов и ожидание человека.

## Разделение знаний (слои)

| Слой | Файлы | Роль |
|---|---|---|
| Постоянные инструкции | `AGENTS.md` (+ стейджинг `docs/agents-md-staged.md`) | читается всегда, короткий |
| Методические знания | `knowledge/skills/*/SKILL.md`, карта — `knowledge/index.md` | progressive disclosure: грузится по задаче |
| Материалы проекта | `project/materials/`, `project/evidence/ev-NNN` | just-in-time по ссылке из артефакта |
| Состояние задачи | `STATE.md` (resume-карта) + `LOG.md` (журнал, append-only) | перечитывается на каждом шаге |
| Стоимость | `COST.md` (dev/prod) | хук `cost-append` пишет строку на сообщение |

## Инструменты

- **14 детерминированных гейтов** (`scripts/check_*.py`): источники,
  evidence-ссылки, цитаты, переносимость, варианты, решения, приёмка,
  управляемость, сложность, диапазоны, состояние, индекс навыков,
  состав коммита, типы. Каждый — с явным кодом возврата и тестами.
- **Хук** `.opencode/plugins/strategy-hooks.ts`: гейты на записи
  `project/*` и `knowledge/*`, `check_state.py` на `STATE.md`, учёт
  стоимости на каждом ассистентском сообщении; лог — `.opencode/hooks.log`
  (вне git).
- **Стенд измерений** `eval/`: рубрики 1:1 из критериев хакатона,
  A/B-руки (`run_ab.py`), полный путь (`run_full_case.py`), критик
  (`run_critic.py`), ось слепых зон (`blindspot_axis.py`), бенчмарк
  DABstep в Docker.
- **Самоулучшение навыков** `product/agent/`: журнал мутаций (JSONL +
  блобы sha256), предохранитель «только по замеру», откат fail-closed.

## Работа с контекстом

- **Контракт сессий**: входы (навык + шаблон + входящие артефакты)
  передаются инлайном в промпт; файлы сессия не открывает; артефакт
  возвращается ответом в чат. Причина — дефект, найденный живым
  прогоном: при контракте «открой файлы инструментами» финальный текст
  терялся на границе CLI/провайдера (37 170 out-токенов в счётчике
  сессии, 48 байт в stdout; $0.25 потеряны). Плюс порог годности
  артефакта (≥2000 символов + markdown-заголовок) — заглушка не даёт
  «вакуумный зелёный» гейтам.
- **Большие промпты** режутся `chunk_prompt` (защита от E2BIG на
  >128 КБ argv; промпты шагов 2–5 — 45–89 КБ).
- **Изоляция критика**: свежая сессия, только артефакт + рубрика
  инлайном, доступ к файлам запрещён инструкцией. Ограничение названо:
  изоляция уровня промпта, не sandbox.
- **Resume**: `STATE.md` — единая resume-карта; новый чат засеивается из
  неё (`skill_view` → навык `resume`). Реальный прецедент: внешний
  SIGINT убил сессию задачи 18 на середине — продолжение с места
  остановки без потери шага.
