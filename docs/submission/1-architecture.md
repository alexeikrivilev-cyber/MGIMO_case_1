# 1. Архитектура

## Что это

«Стратег» — ИИ-агент как репозиторий-папка: инструкции (`AGENTS.md`),
база знаний (`knowledge/`), шаблоны (`templates/`), инструменты
(`scripts/`, `.opencode/`), состояние задачи (`STATE.md`, `LOG.md`,
`COST.md`) и материалы проекта (`project/`). Открывается в средах типа
Cursor / Claude Code / GigaCode / Codex / OpenCode; целевая среда
разработки и прогонов — OpenCode CLI.

## Процессы

Workflow с шагами и чекпоинтами (AGENTS.md §1):

```
Запрос РП
   ▼
[Шаг 0] РАМКА ──────────── ЧЕКПОИНТ 1 (человек подтверждает рамку)
   ▼
[Шаг 1] МАТЕРИАЛЫ ─────── (человек может догрузить/отклонить источники)
   ▼
[Шаг 2] ИССЛЕДОВАНИЕ ──── ЧЕКПОИНТ 2 (человек утверждает план/решающие вопросы)
   ▼
[Шаг 3] ВАРИАНТЫ ──────── ЧЕКПОИНТ 3 (человек выбирает вариант или возвращает)
   ▼
[Шаг 4] СТРАТЕГИИ (продукт + коммуникация + план проверки)
   ▼
[Шаг 5] ПОСЛЕ РЕШЕНИЯ: decisions.md, пересмотр при новых данных
```

Правила шагов: уточнять только то, что меняет следующий шаг (не более
3 обязательных чекпоинтов на прогон); на чекпоинте — сводка «что
известно / чего не знаем / что решаем»; останов и ожидание человека.

## Разделение знаний (слои)

| Слой | Файлы | Роль |
|---|---|---|
| Постоянные инструкции | `AGENTS.md` (+ стейджинг `docs/agents-md-staged.md`) | читается всегда, короткий |
| Методические знания | `knowledge/skills/*/SKILL.md`, карта — `knowledge/index.md` | progressive disclosure: грузится по задаче |
| Материалы проекта | `project/materials/`, `project/evidence/ev-NNN` | just-in-time по ссылке из артефакта |
| Состояние задачи | `STATE.md` (resume-карта) + `LOG.md` (журнал, append-only) | перечитывается на каждом шаге |
| Стоимость | `COST.md` (dev/prod) | хук `cost-append` пишет строку на сообщение |

## Инструменты

- **14 детерминированных гейтов** (`scripts/check_*.py`): источники,
  evidence-ссылки, цитаты, переносимость, варианты, решения, приёмка,
  управляемость, сложность, диапазоны, состояние, индекс навыков,
  состав коммита, типы. Каждый — с явным кодом возврата и тестами.
- **Хук** `.opencode/plugins/strategy-hooks.ts`: гейты на записи
  `project/*` и `knowledge/*`, `check_state.py` на `STATE.md`, учёт
  стоимости на каждом ассистентском сообщении; лог — `.opencode/hooks.log`
  (вне git).
- **Стенд измерений** `eval/`: рубрики 1:1 из критериев хакатона,
  A/B-руки (`run_ab.py`), полный путь (`run_full_case.py`), критик
  (`run_critic.py`), ось слепых зон (`blindspot_axis.py`), бенчмарк
  DABstep в Docker.
- **Самоулучшение навыков** `product/agent/`: журнал мутаций (JSONL +
  блобы sha256), предохранитель «только по замеру», откат fail-closed.

## Работа с контекстом

- **Контракт сессий**: входы (навык + шаблон + входящие артефакты)
  передаются инлайном в промпт; файлы сессия не открывает; артефакт
  возвращается ответом в чат. Причина — дефект, найденный живым
  прогоном: при контракте «открой файлы инструментами» финальный текст
  терялся на границе CLI/провайдера (37 170 out-токенов в счётчике
  сессии, 48 байт в stdout; $0.25 потеряны). Плюс порог годности
  артефакта (≥2000 символов + markdown-заголовок) — заглушка не даёт
  «вакуумный зелёный» гейтам.
- **Большие промпты** режутся `chunk_prompt` (защита от E2BIG на
  >128 КБ argv; промпты шагов 2–5 — 45–89 КБ).
- **Изоляция критика**: свежая сессия, только артефакт + рубрика
  инлайном, доступ к файлам запрещён инструкцией. Ограничение названо:
  изоляция уровня промпта, не sandbox.
- **Resume**: `STATE.md` — единая resume-карта; новый чат засеивается из
  неё (`skill_view` → навык `resume`). Реальный прецедент: внешний
  SIGINT убил сессию задачи 18 на середине — продолжение с места
  остановки без потери шага.

## Почему именно такая организация: программа измерений

Архитектура — не выбор по вкусу, а вывод из 20 задач стенда, каждая
с предрегистрацией (гипотеза и правило вердикта — ДО прогона). Полные
протоколы — `docs/research/measurements.md`; здесь — программа и то,
что она определила.

| # | Вопрос | Метод | Результат | Что определило в архитектуре |
|---|---|---|---|---|
| 1 | Реально ли «агент лучше чата» и за счёт чего? | Абляция слоёв L0→L4, прямой вызов API (среда генерации = промпт), демо + held-out, шум судьи измерен (§23.5) | чат 24/25 → продукт 39/40 / 40/40 (типовая рубрика, MDD 4.08) | прирост несут инструкции и навыки |
| 2 | Усиливается ли «остаток агента» при повторах? | Серия k=3 по слоям, t-интервалы (§24.1) | +4.0 ± 4.1, интервал накрывает 0 | продукт не раздувается ради остатка |
| 3 | Помогает ли «улучшатель» на критике? | 4 независимых измерения (§22.4/§22.7/§23.6/H-C2) | прироста выше шума нет; 2-й раунд ревизии деградирует 26/36→10/36 | критик = детектор, не «улучшатель» |
| 4 | Ловит ли гейт проверки реальные дефекты? | Детектор на артефактах шагов 4–5 + ручная разборка (§22) | 44 находки, ~93% подтверждены; балл не поднимает | гейты встроены в хук как запрет |
| 5 | Нужен ли «Консилиум» и в каком составе? | council-lite vs база; полный протокол vs council-lite (§14/§16) | council-lite +4/+4; полный +2 < MDD при цене 5.7× | прод — council-lite, полный — dev |
| 6 | Триггер «высокая ставка»? | Срабатывания/пропуски (§14) | 10/10, 0 пропусков | триггер оставлен |
| 7 | Какой дизайн библиотеки навыков? | k=3 курация/lean/hybrid (§25) + слепые пары с суждением человека (§26.3) | замерами различия нет; человек: курация 3-0 | решение по человеку; замер назван неразрешающим |
| 8 | Порог «числа правок» как предиктор? | Корреляция на прогонах | r=+0.23 — не подтверждён | метрика отбракована |
| 9 | Можно ли доверять самооценке? | Два изолированных критика на форках + суждение владельца (§30) | вердикт «не подтверждён» (покрытие 2 из 10) | оценка = proxy; человек — ground truth |
| 10 | Аналитическое ядро на реальных данных? | DABstep в Docker, dev-10, официальный scorer (§15) | 7/10, $1.27; оба провала разобраны | proxy-замер с пометкой proxy |
| 11 | Работает ли самоулучшение навыков? | Предохранитель «запись только по замеру» + негативный контроль | отказ на заметке вместо замера | предохранитель в проде |
| 12 | Устойчиво ли продолжение после перерыва? | Внешний SIGINT посреди task 18 (`98d17d6`) → resume из STATE.md новым чатом → зелёный (`3b0cc84`) | прецедент есть; демо-прогон непрерывен (названо в `eval/runs/t18-case/artifacts/decisions.md`), возобновление показано held-out прогоном | resume — часть продукта; хеши — по текущей истории |

Дефекты стенда, найденные живыми прогонами и закрытые по классу
(с регрессиями): потеря финального текста сессии на границе
CLI/провайдера (контракт → инлайн-входы + порог годности); пустой выход
критика при exit=0 (раньше давал ложный «зелёный» — теперь гейт падает);
парсер частичной оценки (менял знак Δ серии — серия пересчитана);
дефект изоляции стенда (§23.0: конфиг репозитория внедрял инструкции в
A/B-руки — операционное правило: чистый L0/L1 только прямым вызовом);
гонка метки прогона (вынесена в `eval/.cost-label`). Провальные и
отвергнутые прогоны сохранены и опубликованы, не спрятаны.
