# 4. Реализованные возможности дополнительного уровня

Каждая строка — с вердиктом замера (подробные протоколы —
`docs/research/measurements.md`). Правило владельца: фича остаётся в
продукте только с подтверждённой пользой или как прямое требование ТЗ;
неподтвердившиеся — названы отрицательными результатами.

| Возможность ТЗ | Реализация | Замер / вердикт |
|---|---|---|
| Поддержка решений (связь решений с ответственными, показателями, условиями пересмотра) | шаг 5: `project/decisions.md`, реестр D1–D4 (владелец, дата, метрика и порог, условие пересмотра, статус); навык `decisions`; гейт `check_decisions.py` | прямое требование ТЗ; гейт зелёный (4/4 решения полны) |
| Пересмотр при новых данных | «История пересмотров» append-only; правило при опровержении предрегистрировано в `verification-plan.md` (2 цикла без роста → откат; возврат отвергнутого варианта — только решением человека) | прямое требование ТЗ |
| Маршрутизация (routing) | `docs/routing.md`: процесс/модель/инструмент по шагу + лог решений с причинами | прямое требование ТЗ |
| Навыки (skills) | 9 навыков в `knowledge/skills/`, progressive disclosure, черновики в `_draft/` | абляция §23.5: +навыки дают +7/+6 к слою инструкций (выше MDD) |
| Хуки (hooks) | `.opencode/plugins/strategy-hooks.ts`: гейты на записи, учёт стоимости | 6 тестов на живом хуке (python-проба через node) |
| Субагенты / изоляция | критик с изолированным контекстом (свежая сессия, инлайн-входы) | механизм оправдан как детектор (§12); два критика — протокол §26 (согласие измерено) |
| Устойчивость к сбоям | retry с деградацией, восстановление STATE.md (`recover_state.py`), порог годности артефакта, chunk_prompt | 3 fault-injection прогона; реальные сбои 502/E2BIG/SIGINT закрыты (§5) |
| Продолжение после перерыва | `STATE.md` + навык `resume` | реальный resume после внешнего SIGINT (task 18) и после прерывания шага 1 |
| Прозрачность | `LOG.md` (append-only), `COST.md` + хук cost-append, manifest прогонов с кодами гейтов и sha256 | прямое требование ТЗ |
| База знаний: навигация, память между сеансами, исправление устаревших записей | `knowledge/index.md` (роутер), журнал мутаций навыков `product/agent/` (блобы sha256, откат fail-closed) | предохранитель «только по замеру» + негативный Control |
| Анализ данных (воспроизводимые расчёты) | 97 срезов демо + 40 срезов held-out пересчитаны из CSV двумя скриптами; 0 расхождений с evidence | `eval/runs/t8-evidence/recompute-*.md` |
| Сравнение с исходным способом | B11: обычный чат на том же брифе — 14/40, 0 URL, $0.06; агент — 39/40 (абляция) | замер есть; вход чата назван неэквивалентным там, где он отвечал на вопрос целиком |
| Бенчмарки из открытых репозиториев | DABstep (Adyen/HF, CC-BY-4.0) в Docker на step-5: dev-10, четыре прогона (§20.7) — 7/10 ($1.27) база, 5/10 ($0.86) улучшенный, 5/10 ($1.10) и 5/10 ($0.66) повторы; стабильных задач 6/10 | шум ±2 задачи доминирует: повтор того же базового агента дал 5/10; стенд — smoke-тест, не характеристика |
| Консилиум (оригинальная фича владельца) | протокол 5 ролей, dev-полный / prod-lite (3 роли, один раунд, триггер высокой ставки) | council-lite +4/+4 против базы (§14); полный — +2 < MDD при 5.7× цены (§16); триггер 10/10 |
| Агент-критик вместо внешнего эксперта | навык `critic` + рубрики 1:1 из критериев + два протокола оценки | прирост несёт детекция, не «улучшение»: 4 отрицательных измерения улучшательных гипотез (§22.4/§22.7/§23.6/H-C2/H-SI1) |
| Слепое попарное тестирование (человек-судья) | 10 пар, ослепление по seed 20261117, ключ после суждения | суждения владельца зафиксированы: skill 2-0, курация 3-0 над lean |
| Самоулучшение навыков | журнал + предохранитель «патч только по замеру» + откат | H-SI1: единая Δ +0.67 ± 9.07 → механика = дисциплина учёта (§28.2) |

Отдельно: **интервью и модельные респонденты, изображения/аудио/видео,
разбор интерфейсов** — не реализованы осознанно (вне кейса, синтетические
ответы за реальные не выдаются); интеграции через MCP — отклонены
замером (см. §2).
