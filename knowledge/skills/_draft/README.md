# knowledge/skills/_draft/ — черновики навыков (стадирование, M3)

Каталог стадирования навыков по механике M3 декомпозиции mattpocock
(`docs/research/mattpocock-decomposition.md` §4, §13): аналог bucket'ов
`in-progress` у mattpocock — «beta: public on purpose, feedback wanted,
not shipped». Новый или изменённый навык живёт здесь, пока не доказан.

## Правила каталога

1. **Черновик не в роутере.** Навыки из `_draft/` намеренно отсутствуют
   в `knowledge/index.md` — иначе роутер врастёт («роутер не врёт»,
   M2/M11). Исключение для `_draft` названое в
   `scripts/check_skill_index.py`: гейт требует синхронности индекса
   только с выпущенными навыками.
2. **Выпуск — только решением PO/владельца и с замером.** Основание
   правила — человеческий ground truth BRIEF п.27: курация 3:0 над
   lean; решения по дизайну инструкций принимает человек, агент
   предлагает. Выпуск без замера = тот же дрейф, против которого
   написан предохранитель самоулучшения (`product/agent/skill_guard.py`).
3. **В каждом черновике — статус.** Секция «Статус» в SKILL.md: что
   осталось измерить, какая секция measurements.md будет основанием
   выпуска. Черновик без статуса — мусор, удаляется на ретро.
4. **Правки выпущенного навыка** тоже проходят через `_draft/` только
   если меняют метод; точечные правки с evidence идут через журнал
   `product/agent/skill_evolve.py` (предохранитель «только по замеру»).
5. **Ретро очереди** (навык `queue-retro`, этот же каталог) решает
   судьбу черновиков: выпустить / оставить / удалить — с причиной.
