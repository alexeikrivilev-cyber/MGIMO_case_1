# Пример: полный диалог с агентом «Стратег» — от развитого вопроса до реализованного продукта

Это запись РЕАЛЬНОГО прогона демо-задачи `demo-retention` (2026-11-17,
модель `stepfun/step-5-preview`, драйвер `eval/run_full_case.py`).
Ничего не додумано: промпты — те, что драйвер отправлял сессиям; выводы
гейтов и строки критика — из записей прогона. Где текст сокращён, стоит
`…` и указан файл-источник. Доказательство каждой строки — в
[`proof.md`](proof.md).

Что демонстрирует пример: **агент не бросает задачу**. Каждый провал
гейта — не «сдаться», а раунд ревизии с новой попыткой; каждая находка
критика — точечная правка с проверкой целостности; первый полный прогон
целиком упал на последнем гейте — драйвер перезапустился и довёл до
зелёного. Итог — шесть артефактов полного пути, все гейты exit 0.

---

## Шаг 0. Запрос руководителя (как звучит)

> «Я руковожу цифровым сервисом — подписочным онлайн-кинотеатром
> оператора связи ("МегаТВ Онлайн", ~2.1 млн активных подписчиков). За
> полгода удержание на 30-й день упало с 34% до 21%, отток среди
> подписчителей первых 3 месяцев вырос. Нужно разобраться, что
> происходит, и предложить стратегию — продуктовую и коммуникационную.
> Данные: выгрузка по клиентам (открытый датасет IBM Telco Churn как
> аналог структуры наших данных), внутренняя выгрузка когорт (условная,
> для демо). Бюджет на удержание ограничен; время — до конца квартала.»

Источник: `eval/tasks/demo-retention/task.md` (постановка дословно).

**Агент (шаг 0, рамка):** уточняет только то, что меняет следующий шаг —
цель, получателя, ограничения, доступные данные; фиксирует метрики
запроса (удержание D30, отток первых 3 месяцев) и цену вопроса.
Рамка заморожена и вынесена на **ЧЕКПОИНТ 1** — человек подтверждает
рамку до анализа. Артефакт — `project/brief.md`.

## Шаг 1. Материалы

**Агент:** собирает 2–3 открытых источника, каждое сведение — с URL и
датой доступа; сырьё складывается в `project/materials/`, добытые
факты — в `project/evidence/ev-NNN` (одно число — одно основание).
Источники задачи: отраслевые бенчмарки удержания (Mixpanel), открытый
датасет IBM Telco Churn (7 043 клиента), arXiv-работа по драйверам
оттока в телекоме.

## Шаг 2. Исследование

Промпт сессии (драйвер, `RESEARCH_BODY`, сокращенно):

> Ты — агент «Стратег»… выполняешь шаг 2 (ИССЛЕДОВАНИЕ)… Требования к
> выходу: решающие вопросы со статусами (частично / пробел); картина
> ситуации — только с основаниями (ev-N, URL, маркеры); конфликты
> источников — парами, без усреднения; гипотезы со способом проверки;
> именованные пробелы — явно… факт / гипотеза / прогноз разделены.

**Гейт провалил первую версию** (запись прогона,
`eval/runs/t18-case-launch.log`):

```
[research.md] раунд 1: провал ['sources-research.md'] → ревизия
[research.md] гейты зелёные (раунд 2)
```

**Что сделал агент:** раунд ревизии по выводу гейта (промпт
`GATE_FIX_PROMPT`: «Находки гейтов механические… Исправь по существу.
Не подгоняй под гейт: не ослабляй возражения, не удаляй пробелы и не
меняй числа»). Вторая версия — зелёная. Артефакт — `project/research.md`.

## Шаг 3. Варианты

Промпт сессии (драйвер, `OPTIONS_BODY`, сокращенно):

> Ты — агент «Стратег», выполняешь шаг 3 (ВАРИАНТЫ)… Требования к
> выходу: не менее трёх вариантов с РАЗНЫМИ механизмами воздействия
> (не разным размером бюджета) + «оставить как есть» с ценой
> бездействия; у каждого: суть / что требует / экономика / сильные
> возражения…

Здесь прогон показал, что такое «не бросать» по-настоящему. Первый
полный путь (запись в `eval/runs/t18-case-launch.log`):

```
[options.md] раунд 1: провал ['sources-options.md'] → ревизия
[options.md] раунд 2: провал ['options'] → ревизия
[options.md] раунд 3: провал ['transferability-options.md'] → ревизия
[options.md] итог гейтов: {..., 'ranges': 2}
RUNNER_EXIT=4
```

Три раунда ревизии — и прогон всё равно остановлен: гейт `ranges`
(диапазон без основания в строке) дал exit=2. Драйвер не сделал вид,
что всё хорошо: он завершился с ненулевым кодом. Затем — перезапуск:

```
== полный путь demo-retention → …/eval/runs/t18-case
[options.md] раунд 1: провал ['sources-options.md'] → ревизия
[options.md] гейты зелёные (раунд 2)
```

Важная деталь контракта: зелёные артефакты переиспользуются
(идемпотентность), поэтому перезапуск не оплачивает пройденное заново —
он добирает только то, что было красным. Артефакт — `project/options.md`
(4 варианта с разными механизмами + «оставить как есть» с ценой
бездействия + блок возражений).

## Шаг 4. Стратегии: продукт, коммуникация, план проверки

Три артефакта, каждый под своим навыком и шаблоном. Реальные раунды
(из `eval/runs/t18-case/manifest.md`):

```
- strategy-product.md: session1 exit=0, символов в выходе 17894
- strategy-product.md: раунд 1 — провал гейтов: ['transferability-strategy-product.md'] → ревизия
- strategy-product.md: раунд 2 — провал гейтов: ['transferability-strategy-product.md', 'acceptance', 'actionability'] → ревизия
- strategy-product.md: гейты зелёные (раунд 3)
- strategy-comms.md: гейты зелёные (раунд 1)
- verification-plan.md: гейты зелёные (раунд 1)
```

**Критик-детектор** (изолированная сессия, только артефакты + рубрика
1:1 из критериев хакатона) — 7 находок «важно» на пакете шага 4. Две
реальные (дословно из `eval/runs/t18-case/critic4/findings.md`):

> 3. [важность: важно] … вторая метрика запроса РП есть в плане
> проверки, но отсутствует в продуктовой стратегии: ни строки в таблице
> метрик, ни владельца инициативы… → добавить строку метрики в
> продуктовую стратегию либо явную делегацию с указанием дома.

> 6. [важность: важно] Пакет в целом… README и сквозной запуск,
> зафиксированный resume между сессиями, held-out задача, COST.md и
> measurements.md в пакет не включены → оценщик снижает баллы за
> непроверяемость… → включить в пакет оценщика выдержки с датами.

Применение находок — точечными патчами с integrity-гейтом (запись
прогона): `applied=7 not_found=1 ambiguous=0 rejected=3 integrity=ok`.
Отказ трёх патчей — не сбой:integrity-гейт не даёт правке сломать
структуру артефакта (заголовки, «оставить как есть», размер ≥60%).

- критик t18-case-critic5: exit=0

Реестр решений: владелец, метрика, условие пересмотра, дата — по каждому
решению (`check_decisions` exit 0). Артефакт — `project/decisions.md`.

## Финал

```
- ИТОГ: все гейты зелёные
RUNNER_EXIT=0
```

Шесть артефактов полного пути лежат в `project/` и читаются напрямую:
`brief.md` → `research.md` → `options.md` → `strategy-product.md` →
`strategy-comms.md` → `verification-plan.md` → `decisions.md`. Каждый
числовой факт несёт основание в той же строке; пробелы названы
пробелами; «оставить как есть» — с ценой бездействия.

---

## Почему этот пример — не «красивый рассказ»

1. **В нём есть провалы.** Первый полный путь закончился `RUNNER_EXIT=4`;
   раунды ревизии, отклонённые патчи, остановка на гейте — всё в записи.
   Сценарий без провалов был бы признаком подделки.
2. **Каждое утверждение сверяемо.** Файлы-источники указаны и лежат в
   репозитории: журнал прогона, лог запуска, выводы гейтов, находки
   критика, строки стоимости. Способ проверки — в [`proof.md`](proof.md).
3. **Это не одноразовый результат.** Тот же путь пройден на held-out
   задаче («ДомКниг», рост сегмента) — свой журнал со своими раундами
   ревизии: `eval/runs/t18-case-heldout/manifest.md`.
