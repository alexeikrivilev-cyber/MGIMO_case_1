## Конфликты

- Версии схемы датасета: зеркало mlbookcamp — 21 колонка с именами
  `tenure`, `Churn`; на Kaggle (blastchar) распространена 23-колоночная
  версия с `Tenure Months`, `Churn Value`, `Churn Reason`, `City`,
  `Population` (колонки с географией и причиной оттока). Использовано
  зеркало (прямое скачивание без авторизации). Расхождение схем
  зафиксировано: при сравнении с чужими расчётами сверять имена колонок —
  величины оттока при этом совпадают (26.5% churn, ev-003).
  Статус сверки 23-колоночной версии: НЕ ПРОВЕРЕНА — страница Kaggle за
  авторизацией, URL-подтверждения состава 23 колонок нет
  (ре-проверка 2026-11-16, браузер: видны только счётчики 7 043 / 21);
  claim о составе 23-колоночной версии читать как [гипотеза] о схеме,
  не как факт источника (находка критика с дайджестом,
  `eval/runs/h3-probe/`, measurements.md §12.3).
- Величины «month-to-month 42.7% vs 2-year 2.8%» из
  `eval/tasks/demo-retention/materials.md` приписаны arXiv 2608.26151;
  в аннотации arXiv их нет — они воспроизводятся собственным подсчётом
  по датасету (42.71% / 2.83%). Конфликт атрибуции разобран в ev-003.

## Пробелы

- В датасете нет временных меток (нет дат подключения/оттока): когортную
  динамику «первые 3 месяца» во времени восстановить нельзя — только
  срез по длительности tenure на момент выгрузки. Это ограничение для
  решающего вопроса №2 (когорта новичков vs вся база).
- Нет признаков контента, коммуникаций и ценовых событий: проверить
  «продуктовое vs коммуникационное» воздействие на этих данных нельзя
  напрямую — только косвенно через демографию/сервисные признаки.
- 11 строк с пустым TotalCharges — небольшая, но зафиксированная
  неполнота.
