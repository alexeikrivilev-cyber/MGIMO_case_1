# Демо-задача: удержание цифрового сервиса (demo-retention)

Резервная демо-задача хакатона (бриф МегаФона будет опубликован дополнительно;
до появления — используем эту). Только открытые данные и собственные материалы.

## Постановка (как звучит запрос РП)

> «Я руковожу цифровым сервисом — подписочным онлайн-кинотеатром оператора
> связи ("МегаТВ Онлайн", ~2.1 млн активных подписчиков). За полгода
> удержание на 30-й день упало с 34% до 21%, отток среди подписчиков
> первых 3 месяцев вырос. Нужно разобраться, что происходит, и предложить
> стратегию — продуктовую и коммуникационную. Данные: выгрузка по клиентам
> (открытый датасет IBM Telco Churn как аналог структуры наших данных),
> внутренняя выгрузка когорт (условная, для демо). Бюджет на удержание
> ограничен; время — до конца квартала.»

## Что проверяет задача (соответствие ТЗ)

- Постановка: уточнить цель, получателя, ограничения, доступные данные (шаг 0).
- Материалы: 2–3 открытых источника, каждое существенное сведение — с URL и
  датой (шаг 1).
- Дальше (День 3+): исследование → ≥3 варианта (вкл. «оставить как есть») →
  продуктовая + коммуникационная стратегии → план проверки.

## Как запускать

1. Открыть репозиторий в целевой среде (OpenCode: `opencode run` из корня).
2. Промпт шага 0: «Выполни шаг 0 (рамка) по демо-задаче eval/tasks/demo-retention/task.md».
3. После ЧЕКПОИНТА 1 — шаг 1: «Собери материалы по подтверждённой рамке».
4. Прерывание: остановить сессию на середине шага 1; продолжение — новый чат
   с промптом «Прочитай STATE.md и продолжи» (навык `resume`).

## Ограничения и честные оговорки

- «МегаТВ Онлайн» — вымышленный сервис для демо; цифры в запросе РП — часть
  сценария, не реальные данные оператора.
- Датасет IBM Telco Churn — открытый аналог структуры данных, не данные
  вымышленного сервиса; связь «наш сервис = этот датасет» — допущение демо,
  помечается как гипотеза в evidence.
- Бенчмарки Mixpanel — отраслевые, не по нашему сервису; используются как
  внешняя точка сравнения с пометкой источника.
