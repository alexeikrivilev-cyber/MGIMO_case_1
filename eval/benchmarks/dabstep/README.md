# DABstep — открытый бенчмарк на стенде О4 (Docker, step-5)

> Статус: стенд поднят 2026-11-16 (О4, BRIEF п.14). Прогон — dev-контур
> (в разработке не экономим; прод-решение — отдельно).

## Что это и почему именно это

**DABstep (Data Agent Benchmark for Multi-step Reasoning)** — 450
аналитических задач над реальными (анонимизированными) данными
платёжной платформы Adyen; готовили Adyen + HuggingFace. Задачи —
factoid (краткий проверяемый ответ), два уровня сложности (72 easy /
378 hard), оцениваются объективным fuzzy-scorer'ом. Публикуются:
датасет, Baseline-код, официальный scorer, лидерборд.

- Датасет: https://huggingface.co/datasets/adyen/DABstep (CC-BY-4.0,
  дата доступа 2026-11-16)
- Блог/описание: https://huggingface.co/blog/dabstep (2026-11-16)
- Статья: https://arxiv.org/abs/2506.23719
- Официальный scorer (вендорен дословно):
  https://huggingface.co/spaces/adyen/DABstep/resolve/main/dabstep_benchmark/evaluation/scorer.py

**Честная рамка (proxy, не «бенчмарк нашего агента»).** Публичного
бенчмарка, измеряющего «стратегию из папки» (варианты + возражения +
коммуникационная стратегия), не существует — это зафиксировано в
`docs/research/benchmarks.md` §1.12 («honest gaps»). DABstep измеряет
БЛИЖАЙШУЮ по домену способность: **многошаговое аналитическое
рассуждение агента над реальными бизнес-данными с документацией** —
это под-способность нашего шага 1–2 (материалы → исследование →
численные проверки). Результат здесь — прокси для аналитического ядра,
НЕ оценка качества стратегических артефактов (их мерим своей рубрикой,
`eval/rubrics/`).

**Что измеряем:** accuracy (pass/total по официальному scorer'у),
шагов до ответа, токены и $/задачу (прайс step-5-preview §1.8).

## Почему dev-сплит

В публичном датасете ответы даны ТОЛЬКО у dev-сплита (10 задач: 3 easy +
7 hard); у основного сплита (450) колонка ответа пустая (скоринг — на
лидерборде). Поэтому первый прогон — dev-10. Это мало для статистики,
и мы так и пишем: 10 задач дают шум ±1 задача; замер — ориентир
(«agent решает hard-задачи DABstep в X%»), не доказательство.

## Состав

| Файл | Роль |
|---|---|
| `Dockerfile` | ubuntu:24.04 + python3 stdlib (без pandas — см. комментарий внутри) |
| `fetch_data.sh` | качает context-файлы и dev-задачи (вне git, URL внутри) |
| `scripts/agent.py` | ReAct-агент: модель исполняет python-код в контейнере, финализирует «FINAL: …» |
| `scripts/run.py` | прогон сплита → scorer → results.json/results.md |
| `scripts/scorer.py` | вендор официального scorer'а (дословно, провенанс в шапке) |
| `data/` | перекачиваемое сырьё (в git не идёт, см. `.gitignore`) |

## Запуск

```bash
# 1) сырьё (один раз)
bash eval/benchmarks/dabstep/fetch_data.sh

# 2) сборка образа
docker build -t dabstep-stand eval/benchmarks/dabstep

# 3) прогон (ключ — из env хоста, НЕ в образ и не в репозиторий)
mkdir -p /tmp/dabstep-out
docker run --rm --network host \
  -e STEPFUN_API_KEY \
  -v /tmp/dabstep-out:/out \
  dabstep-stand --data /workdir/data/context --tasks /workdir/data/tasks-dev.json --out /out
```

Результаты прогонов складываются в `eval/benchmarks/dabstep/runs/<дата>/`
(comitable) и переносятся в `docs/research/measurements.md` (§ бенчмарки).

## Ограничения (называем явно)

- 10 задач — маленькая выборка; один прогон — один sample (temperature 0,
  но reasoning-модели не гарантируют детерминизм).
- Замеряем под-способность (аналитика), не качество стратегии.
- Модель одна (step-5-preview); сравнения с другими моделями — когда
  появятся ключи (внешних ключей нет, решение PO R5).
- Код исполняет сама модель в контейнере: Meerjkg-риски (модель может
  сломать окружение) изолированы границами контейнера.
