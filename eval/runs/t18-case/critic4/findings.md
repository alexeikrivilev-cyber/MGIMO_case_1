## Findings

1. [важность: важно] АРТЕФАКТ strategy-comms.md, раздел «Что именно просим утвердить», последняя строка («…И2 (модель) и И5»); АРТЕФАКТ verification-plan.md, раздел «Примечание (шаг 4)», последняя строка («вопрос 6 … „Правило при оп») → оба файла обрываются на полу-слове → если усечены и файлы на диске, коммуникационная стратегия не содержит завершённого «что просим утвердить» (ключевого элемента формата «на утверждение»), план проверки — хвоста указателей; если это усечение промпта — артефакты целы → проверить целостность файлов на диске и при необходимости дособрать пакет. При подтверждении на диске — критично.

2. [важность: важно] Межартефактно: strategy-product.md ссылается на `project/strategy-comms.md`, `project/verification-plan.md`, `project/brief.md`; strategy-comms.md и verification-plan.md — на `eval/runs/t18-case/artifacts/strategy-product.md` и `.../options.md` → один и тот же артефакт имеет два «дома» → ломается дисциплина «один дом факта» и проверяемость: strategy-product.md сам сообщает, что гейты прогнаны на копии в структуре `eval/runs/` (правило C в check_sources зависит от пути), т.е. зелёность гейтов на каноническом пути не продемонстрирована → зафиксировать канонический путь каждого артефакта, привести все ссылки к нему, прогнать гейты на канонических путях.

3. [важность: важно] АРТЕФАКТ strategy-product.md, «Метрики и целевые значения» + Q5 приёмочного чек-листа — против АРТЕФАКТА verification-plan.md, строка «Отток среди подписчиков первых 3 месяцев — вторая метрика запроса РП» → вторая метрика запроса РП есть в плане проверки, но отсутствует в продуктовой стратегии: ни строки в таблице метрик, ни владельца инициативы, ни упоминания в Q5 → половина критерия успеха РП не имеет дома в стратегии; приёмочный чек-лист отвечает на вопрос «метрики успеха» неполно → добавить строку метрики в продуктовую стратегию (baseline — названный пробел, цель — после И1) либо явную делегацию с указанием дома.

4. [важность: важно] АРТЕФАКТ verification-plan.md, строка «Абсолютное число подключений — защита от парадокса метрики (И1)», основание «options.md, риски варианта 3 [прогноз]» → страж-метрика обоснована рисками отвергнутого ВАРИАНТА 3, который в выбранной комбинации В1+В2 не участвует → основание цитирует не тот вариант: либо цитата неточна, либо риск заимствован из анализа В3 без пометки заимствования; в артефакте с эталонной дисциплиной маркеров это дыра → уточнить основание (риск В1/В2 или «общий риск измерения»).

5. [важность: незначительно] АРТЕФАКТ strategy-product.md, «Выбранный вариант»: «механизмы непересекающи и потому сочетаются [допущение]» → опечатка («непересекающиеся» / «не пересекаются») в несущем предложении, которым обосновывается сочетаемость выбранной комбинации вариантов → исправить; допущение сочетаемости опирается именно на эту формулировку.

6. [важность: важно] Пакет в целом (для критериев 2–4 рубрики) → README и сквозной запуск (3.1), зафиксированный resume между сессиями (3.3), held-out задача (3.5), COST.md и measurements.md (4.1, 2.2, 4.3) в пакет не включены → оценщик снижает баллы за непроверяемость, хотя механизмы видны по ссылкам из артефактов (навыки, гейты, STATE/LOG, decisions.md, ЧЕКПОИНТЫ 1–3) → включить в пакет оценщика выдержки с датами: команду запуска из README, запись реального resume из LOG.md, строки COST.md по шагам и measurements.md по фичам.
