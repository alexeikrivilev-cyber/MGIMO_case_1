# FI-1 — сценарий fault-injection: «поиск/фетч падает — путь продолжается»

> Прогон устойчивости (PRD §12, ROADMAP B5): один источник недоступен
> (сетевая ошибка), второй — локальный файл. Ожидаемое поведение по
> PRD §12: retry с backoff → деградация: работа с локальными
> материалами + явная запись пробела; ссылка помечается «не проверена».
> Шов неудачи: `http://127.0.0.1:1/dead-source` (порт 1 — соединение
> отказано детерминированно, без ожидания таймаутов).

## Постановка для агента (дословно в промпт прогона)

Ты выполняешь шаг 1 (МАТЕРИАЛЫ) в аварийном режиме fault-injection.

Два источника:
1. Сетевой: `http://127.0.0.1:1/dead-source` — может быть недоступен.
   Добывай ТОЛЬКО через `python3 scripts/fetch_with_retry.py <url> <out>`
   (retry с backoff встроен; при полном отказе скрипт печатает
   запись-пробел — используй её).
2. Локальный: `project/materials/telco-customer-churn.csv` — читай
   напрямую, считай базовые факты (число записей, долю оттока) python3
   (stdlib, без pandas).

Требования к выходу:
- Создай ЕДИНСТВЕННЫЙ новый файл: `eval/fault-injection/fi1-output.md`.
- В файле: запись доказательства по локальному источнику (факты с
  числами + путь к файлу + дата), запись-пробел по сетевому источнику
  (дословно из вывода скрипта, статус «не проверена»), и явный вывод:
  продолжается ли путь и что именовано пробелом.
- Read-only для остального репозитория: не создавай и не редактируй
  другие файлы.
- Язык: русский. Маркеры [гипотеза]/[допущение] — где нужно.

## Ожидаемый вердикт (критерий приёмки FI-1)

1. Скрипт вызван, retry сработал (в логе — попытки и backoff), отказ
   зафиксирован.
2. Локальный источник обработан: числа посчитаны и записаны.
3. Пробел назван явно (не «источник недоступен» вскользь, а
   именованная запись со статусом).
4. Путь продолжился: артефакт создан несмотря на отказ сети.
5. Никаких лишних записей в репозитории (`git status` чист, кроме
   целевого файла).
